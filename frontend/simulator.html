Interior de AES-GCM (Bloques)

AES-GCM funciona cifrando en paralelo. Para el primer carácter de tu mensaje, se realiza la operación XOR con la máscara de flujo generada por el cifrado de contador:

Mensaje Char [0]: 'H' (Hex: 0x48)
Máscara KeyStream: 0xB2
XOR: 0x48 ⊕ 0xB2 = 0xFA
Texto Cifrado resultante: 0xFA ('ú')

Relleno OAEP y Modulo RSA

Para evitar ataques de texto cifrado escogido, la llave AES se concatena con padding OAEP aleatorio. Luego se aplica la exponenciación modular con la Llave Pública RSA $(e, N)$:

Llave AES Simétrica: 0x5f9b...
OAEP Pad Mask MGF1: ✓ Aplicado (Seguridad Semántica)
Fórmula RSA: C = Me mod N
Simulado ($e=17, N=3233$): 6517 mod 3233 = 2790
Llave AES Envuelta: 0xa28f9d14...

Ecuaciones de Lagrange a nivel de Bytes

Con fragmentos en $x_1=1$ y $x_2=3$, los coeficientes de interpolación para encontrar el secreto ($x=0$) son:

l1(0) = x2 • (x2 ⊕ x1)-1 = 3 • (3 ⊕ 1)-1 = 3 • 2-1
En Galois GF(256), 2-1 = 142. Por tanto: 3 • 142 = 213
l2(0) = x1 • (x1 ⊕ x2)-1 = 1 • (1 ⊕ 3)-1 = 1 • 2-1 = 142
S = (y1 • 213) ⊕ (y2 • 142)

Operación en Campo de Galois GF(256)

Para evitar pérdidas de precisión y overflows, la aritmética se ejecuta bajo un módulo polinomial reductor irreducible $x^8+x^4+x^3+x^2+1$ (0x11d):

Suma / XOR (142 ⊕ 213): 10001110 ⊕ 11010101 = 01011011 (91)
Multiplicación (Rusa): Si hay acarreo (>0x80), se aplica XOR 0x11d
Ejemplo de primer byte reconstruido del PEM:
Fragmento 1 (y1) = 0xF3 • 213 = 0x9B
Fragmento 3 (y3) = 0x2A • 142 = 0xCE
Secreto Reconstruido: 0x9B ⊕ 0xCE = 0x55 ('U') ✓

Serialización y Digestión del Buffer

Para calcular el hash de un bloque, todos sus campos se serializan como un único string continuo separándolos con tuberías:

Buffer_Bloque_2 = "2|2026-07-01 00:48:00|REPORT_SUBMITTED|Anónimo|Detalle: Denuncia registrada ID #1|9b8a6caa807101fe9166f1d4f3e565397b628b8ca1f1d264fd2f9822e86898"

Propiedades SHA-256 contra Colisiones

SHA-256 posee **efecto avalancha**: modificar un solo caracter en el buffer (ej: cambiar "Denuncia registrada ID #1" a "Denuncia registrada ID #2") cambia de forma radical el hash digestivo:

SHA256(Original) = 53d2888ce859dd3dc...
SHA256(Modificado) = 8ae9bd271f28e69d0...
Como el Bloque 3 calcula su hash alimentándose de SHA256(Buffer_Bloque_2), su hash calculado cambia también de forma drástica, propagando la falla infinitamente.
